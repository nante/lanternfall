**Material findings**

- [Authoritative state and saving](/Users/kubawiszniewski/Personal/game/docs/BUILD-PLAN.md:103): Receipt replay and session fencing need one explicit handshake. A crash after commit but before acknowledgement may be followed by a new login that fences the old epoch. Specify how an authenticated player resumes or queries that old epoch’s receipt before issuing a new action. Persist the sequence watermark and request identity, define gap handling, and record outcomes for admitted rejected or no-op commands too—even when the world snapshot did not change. A reused sequence with different input must be rejected.
- [Authoritative state and saving](/Users/kubawiszniewski/Personal/game/docs/BUILD-PLAN.md:107): Make “full dynamic snapshot” explicit about creature positions and targets, dynamic doors, and remaining movement, attack and healing deadlines. Restore paused simulation timers as remaining durations; process wall-clock corpse expiry before reconnect. This prevents a restart from combining persisted HP with reset positions or cooldowns.
- [First playable loop and contents](/Users/kubawiszniewski/Personal/game/docs/BUILD-PLAN.md:63): For every nested-container operation, revalidate the entire parent chain through to an accessible root. That includes reach, floor, corpse ownership/expiry and personal-depot ownership, even if a child panel was already open. Invalidate descendant access when the root becomes inaccessible or expires.
- [Difficulty configuration v0](/Users/kubawiszniewski/Personal/game/docs/BUILD-PLAN.md:89): Define the starting cumulative skill-training baseline, loss rounding and minimum skills; otherwise “lose 5% of skill training” can mean no loss at the initial skill 20. Also specify derived HP/mana on level loss and the temple respawn HP/mana. The first death immediately drops the starting character below level 8, so these are needed for the recovery loop.
- [Difficulty configuration v0](/Users/kubawiszniewski/Personal/game/docs/BUILD-PLAN.md:97): State what happens when the disconnect lock expires: persist and remove an unlocked disconnected character, and resolve death and temple respawn if they die while disconnected. Apply the same lock to voluntary logout. Define a single monster-kill XP recipient and corpse access rule—for example, last hitter—so two clients cannot each receive the same reward.
- [Executable build sequence](/Users/kubawiszniewski/Personal/game/docs/BUILD-PLAN.md:130): Increment 2 introduces damaging combat, while player death arrives in increment 3. Add a minimal, nonduplicating lethal outcome in increment 2, then complete the selected death penalties and recovery in increment 3. Also distinguish reaching the depot in increment 1 from actually storing and retrieving items in increment 2; the map section currently asks the first implementation to “use the depot.”
- [Visual treatment](/Users/kubawiszniewski/Personal/game/docs/BUILD-PLAN.md:120): Move a small readability experiment forward into the walk increment: one rigged actor and a representative textured street/occlusion piece, checked in motion and on resize. That satisfies the brief’s early actor-pipeline check without reopening the chosen glTF direction or building the full art kit early.
